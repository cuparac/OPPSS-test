KRATAK PREGLED:
U odnosu na v13.6, u v13.7 je popravljeno 8 problema (2 visokog, 3 srednjeg i 3 niskog prioriteta).
Sada radi ispravno i na Windows-u i na Unix/Mac sistemima.

================================================================================
ISPRAVKE:
================================================================================

1. [VISOKO] assert iznos > 0  (linija ~608)
   Problem: assert se NE izvrsava ako se Python pokrene sa -O (optimize) flagom.
            Iznos 0 ili negativan bi prosao validaciju!
   Resenje: Zameno sa "if iznos <= 0: raise ValueError"
   Status: ✅ ISPRAVLJENO

2. [VISOKO] fcntl.flock() - ne radi na Windows  (linija ~72)
   Problem: fcntl je Unix/Mac modul. Na Windows-u aplikacija pada.
   Resenje: Dodat platform check. Na Windows se koristi atomic write
            (write to temp file, then os.replace).
   Status: ✅ ISPRAVLJENO

3. [SREDNJI] subprocess.run bez check=True  (linija ~18)
   Problem: Ako "pip install lxml" ne uspe, sledeca linija pada u ImportError.
   Resenje: Dodato check=True - ako install padne, odmah se baca exception.
   Status: ✅ ISPRAVLJENO

4. [SREDNJI] Nema provere datum_do >= datum_od  (sacuvaj funkcija)
   Problem: Korisnik moze uneti kraji datum pre pocetnog.
   Resenje: Dodata provera - ako je datum_do < datum_od, prikazuje se greska.
   Status: ✅ ISPRAVLJENO

5. [SREDNJI] Tabela prikazuje samo jedan datum  (osvezi_tabelu)
   Problem: Tabela je prikazivala samo jedan datum, ne "od/do" period.
   Resenje: Sada prikazuje "DD/MM/YYYY - DD/MM/YYYY" format.
   Status: ✅ ISPRAVLJENO

6. [NIZAK] generisi_xml cita isti XML fajl dvaput sa diska  (linija ~256)
   Problem: XML se pise na disk, pa se opet cita za validaciju.
   Resenje: Validacija se vrsi direktno iz memorije (root objekta).
   Status: ✅ ISPRAVLJENO

7. [NIZAK] replace(" ", "") - brise samo space  (linija ~318)
   Problem: Ako korisnik unese tab ili drugi whitespace, ne brise se.
   Resenje: Koristi se .strip() za uklanjanje svih whitespace sa krajeva.
   Status: ✅ ISPRAVLJENO

8. [NIZAK] Nema error handling za korumpirani JSON  (ucitaj_bazu)
   Problem: Ako je JSON fajl ostecen, aplikacija pada.
   Resenje: Dodat try/except za JSONDecodeError i IOError.
            Prikazuje upozorenje i kreira praznu bazu.
   Status: ✅ ISPRAVLJENO
